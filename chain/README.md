# chain

`svnd` is the application binary of the permissioned beta. It uses Cosmos SDK v0.55.0 and CometBFT v0.40.0. It is not a release, and public launch is disabled.

The binary wires auth accounts, signatures, sequences, transaction size, and gas limits. It registers the six module slots from the blueprint:

| Module | State | Messages |
| --- | --- | --- |
| `x/authority` (Goal 06) | Validator set, admitted accounts, devnet council, proposals | `ProposeChange`, `ApproveChange`, `ExecuteChange` |
| `x/providers` (Goal 07) | Provider registry | `RegisterProvider`, `UpdateProvider`, `RotateProviderKey`, `DrainProvider` |
| `x/content` (Goal 07) | Content coordination registry and tombstones | `RegisterContent`, `WithdrawContent` |
| `x/leases` (Goal 08) | Lease offers, leases, capacity reservations (in the provider records), expiry indexes | `OfferLease`, `AcceptLease`, `RenewLease`, `EndLease`; BeginBlock expiry |
| `x/evidence` (Goal 09) | Signed audit attestations of held leases (records, batch ids, per-auditor round counters); a record is an attestation, not a storage proof | `SubmitAuditBatch` (AUDITOR accounts only); no BeginBlock: a record's EXPIRED state is computed at read time |
| `x/policy` (Goal 10) | Safety caps, governed limits and their pending changes, the upgrade plan and applied upgrades, the module version map, the app version | None: changes only through an executed council proposal; BeginBlock applies the governed changes due at the block |
| `svn` | Genesis header, consensus parameters | None (scaffold slot, DR-10-28) |

`x/authority` is the only module that returns validator updates. It runs the council proposal flow of Goal 06: four devnet seats propose and approve, the authority submitter executes, and the validator set changes in EndBlock at the activation point. See `x/authority/README.md`. Council admission, disablement, and forced withdrawal are council payloads executed through `x/authority`; there is no single-signer admit, disable, or force-withdraw message (DEC-009). Business ids are one namespace across authority, providers, content, leases, and evidence. A withdrawal (message or council) voids the content's open lease offers in the same transaction. An `ACTIVE` lease is a committed obligation with a reservation, not evidence of retrieval or publication; see `x/leases/README.md` and `docs/architecture/leases.md`. An evidence record says that an admitted auditor signed a statement about one lease; the chain compared two digests and fetched nothing, and no evidence record renews, extends, or revives a lease; see `x/evidence/README.md` and `docs/architecture/evidence.md`. Policy has no message service: a governed limit, its activation height, an upgrade plan, its cancellation, and a council seat key change only through a council payload that `MsgExecuteChange` executes (protocol schema version 2, `docs/protocol.md` "Goal 10 additive revision"); see `x/policy/README.md`.

The upgrade runner (`chain/upgrade`, Goal 10) checks the binary against the committed state. At load, `app.New` runs the load gate after the last committed block and refuses (svnd exits 1 before CometBFT starts) unless the binary is the one for the next block, or the binary of the upgrade that applies in the next block. In PreBlock of every block, before any module, it refuses a block whose stored app version differs from the binary's, and at the plan height it runs the upgrade's handler and migrations in a cache context that is written only after every post-condition passed (`docs/architecture/governance-and-upgrades.md`, PROPOSED). InitChain refuses a binary whose app version is not 1. The default svnd build (no build tag, the only release build) compiles no upgrade handler; `-tags svn_rehearsal`, `svn_rehearsal_bad`, and `svn_statecheck` build devnet-only test variants that start only on a `shortvideo-dev-` chain id (orchestrator choice ORCH-6, not an owner decision). `svnd version` prints the app version, the module versions, and the compiled upgrades.

Queries: `svn.providers.v1.Query` (`Provider`, `Providers`), `svn.content.v1.Query` (`Content`), `svn.leases.v1.Query` (`ActiveLeases`, `Deadlines`), `svn.evidence.v1.Query` (`Evidence`, by evidence id or by lease, with the state reported at the query height's header time), `svn.policy.v1.Query` (`Policy`), and `svn.authority.v1.Query` (`Governance`) are served by ABCI query (`/svn.providers.v1.Query/Provider` and so on, with a height) and by the node gRPC server. The REST gateway is disabled. Every gRPC-routed query (ABCI query on a registered service path such as `/svn.providers.v1.Query/Provider`, and the node gRPC server) runs on a gas meter limited to `query_gas_limit` in `node.json`, or 20,000,000 (the transaction gas cap; a proposed node default, decision request DR-07-10) when it is absent or 0. The meter is finite unless an operator sets 2^64-1, which the SDK treats as unlimited. Raw store queries (`abci_query` on `/store/<store>/key` or `/store/<store>/subspace`) are not: the SDK serves them from the IAVL store with no gas meter and no page cap, so a subspace query returns every row under a prefix. Do not expose the CometBFT RPC port publicly (residual risk; see `x/providers/README.md`). See `x/providers/README.md` and `x/content/README.md`.

A registry entry is a coordination record. It is not copyright proof, a hosting receipt, or publication approval. The protocol has no field for endpoint URLs, manifests, media bytes, or personal data; the chain stores digests, byte counts, ids, and states. Unknown fields (critical and non-critical) fail transaction decoding, and the ante handler rejects a memo, a fee payer, a fee granter, and a tip. Ids are still text the submitter chooses: an email or a URL does not match the id pattern and is rejected (`BOUNDS`, or `NOT_FOUND` where the handler looks the id up first; nothing is stored either way), but an id-shaped value such as a username is stored as given, and a transaction a handler rejects stays in its block. Opaque ids and digests can still be linkable.

Staking, bank, mint, distribution, slashing, governance-by-token, EVM, and IBC are not imported. There is no coin denomination and no fee amount.

`make devnet-up` starts four processes on one machine. `make devnet-down` stops them without deleting genesis. `make devnet-resume` starts the same homes again. The devnet genesis has runtime-generated accounts `authority`, `service`, `service-2`, `provider-1`, `provider-2`, `broadcaster` (secp256k1), `auditor-1` and `auditor-2` (`AUDITOR`, ed25519: the same key signs their transactions and their attestations; one operator on one machine, not independent auditors), and four council seats; their keys stay under the home directory and are never committed. The seats have auth accounts but no submitter row: the ante admits them from the seat list and lets them sign only propose and approve (DR-06-06). `go test ./chain/devnet -run TestDevnetRegistryDemo -v` runs the Goal 07 registry demo, `go test ./chain/devnet -run TestDevnetLease -v` the Goal 08 lease demos, and `go test ./chain/devnet -run TestDevnetAudit -v` the Goal 09 audit demo (the `agents/auditor` producer, built by the test, against a loopback HTTPS test endpoint) against four real processes on one machine (not independent operators).
