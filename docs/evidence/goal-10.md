## Residual risks

Threat notes (DR-10-19): governance capture, a malicious upgrade binary, the single executor, a minority skip and prior-release divergence are recorded here, not in `docs/threat-model.md`.

- An upgrade binary can change any rule, cap, quota, seat or decision row. Its self-checks run inside it and protect only against an honest binary's mistakes. The controls are human review of source and digest and each operator's refusal to install; neither is a test. On the devnet one operator holds every seat and every node.
- The handler environment lets a handler write every store other than x/authority and x/policy, and the svn store except the consensus params (`{0x03}`); the svn genesis row `{0x01}` is not protected. B2-bad uses that to diverge. An "svn other rows" I13 class was declined because the svn scaffold store has no layout key.
- Governance capture: three colluding or compromised seats can schedule any upgrade. The owner's Q3 option says so.
- A plan whose binary does not exist halts the chain at h. The council cannot repair a halted chain ("A chain stall can prevent on-chain governance from executing.", `docs/decision-register.md:247`). Only a binary for the plan resumes it.
- The single `AUTHORITY` executor: its loss freezes execution, including any change that would replace it; it chooses when a queued plan executes inside the lead window and may withhold a cancel.
- The prior release (goal 09) has no app-version rule and checks only four registry layouts. An operator who runs it on a goal 10 home may get a diverging node (DR-10-43; not tested).
- A node commits one wrong height before CometBFT detects a wrong migration (I6). Copy-at-halt is the only local recovery without a rollback tool.
- Upgrade window (DR-10-41): a node swapped before block h was decided serves `CheckTx` and queries with new code on old state until h commits; after any start, `CheckTx` rejects normal accounts until the first commit.
- A planned halt makes everything that fell due during it due at h+2, at most 128 items per block. Leases whose deadline falls in the halt cannot be renewed while halted. No maximum planned halt is set (DR-10-39).
- A new node joining after an upgrade must start from the genesis binary and switch at each plan height.
- Migration work runs once in PreBlock with no per-block cap. A large state could make block h slow; it is measured only on the rehearsal state ([Measurements](#measurements)).
- After an upgrade that changes a layout, historical queries and state checks below h through the new binary can misread state.
- The rehearsal walk of proposal records checks only their shape.
- The tagged builds' chain-id restriction reads the genesis file and the genesis document CometBFT stored; it is defence in depth for disposable devnets, not an access control. The state check holds each store's whole snapshot in memory; it is a devnet tool.
- The release digest in a plan is information only. The chain cannot tell which binary a node runs.
- A binary built from a `git worktree` checkout prints `vcs.revision unknown`; release candidates must be built from a clone.
- Raw `/store` queries are unmetered; the CometBFT RPC port must not be public.
- The `EXECUTED` or `REJECTED` to `EXPIRED` relabel stays (spec behaviour).
- Business-id squatting across modules (DR-10-16) is a denial of service, never a wrong transition.
- The devnet rehearsal estimates its crossing times from measured rates (40 s resume allowance, 60 s margin, both PROPOSED test parameters); a slower host fails loudly.
- The CI app shard builds four svnd variants; the `devnet-upgrade` shard must fit its 15-minute `go test` timeout (local sample: `=== shard devnet-upgrade exit 0 seconds 368`, with `ok  	github.com/Maxencejules/shortvideo-network/chain/devnet	346.498s` inside it). One CI sample exists: the `go-race (devnet-upgrade)` job of run 42439476805 ran 02:39:44-02:50:40Z, prebuilds included ([Head CI](#head-ci)); its `go test` time is not recorded here.
- On the two mutants that start a node, the named test binds loopback ports until its go test process exits, and a hung test leaves its temp directory.
- G-11 and the three open parse classes (DR-10-44): both sides reject with different codes; no state changes. The owner accepted this as a recorded difference on 2026-11-08; the fold of the three classes into G-11 is a follow-up.
- A compromised or dishonest auditor cannot be removed on chain (DR-09-08 DEFERRED).
- The devnet is four processes on one machine. Node ids do not prove independent replicas, and one operator decides for every node.
